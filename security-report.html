Security Report

How NebulaScan protects users and their scan history through Zero Trust security principles — where no request, user, or data source is trusted by default.

shield What is Zero Trust?

Zero Trust means never trust, always verify. Every request — whether from a browser, an API call, or an external data source — is treated as potentially hostile. NebulaScan applies this principle across every layer: input validation, rate limiting, data isolation, and anonymous history storage.

speed

Rate Limiting

Every IP is capped at 20 analysis requests per minute using SlowAPI. No source — not even internal — is trusted with unlimited access. Exceeding the limit returns HTTP 429.

Zero Trust Control: Assume every caller could be malicious
rule

Input Validation

All URLs are validated by Pydantic v2 schemas before any processing begins. Length is capped at 2048 characters. Malformed input is rejected immediately — never passed downstream.

Zero Trust Control: Validate every input at the boundary
storage

Anonymous History Storage

Scan history stores only the URL, score, and timestamp. No user identity, IP address, cookies, or session tokens are ever recorded. History is fully anonymous — no one can be linked to a scan.

Zero Trust Control: Minimise data collected to minimise exposure
database

SQL Injection Prevention

All database access goes through SQLAlchemy ORM with parameterised queries. Raw SQL is never constructed from user input. The database layer treats every value as untrusted data.

Zero Trust Control: Never trust data from the client in queries
key_off

No Client-Side Secrets

API keys (Google Safe Browsing, etc.) are loaded server-side via environment variables only. The browser never receives any secret. If no key is configured, the check gracefully degrades instead of exposing credentials.

Zero Trust Control: Secrets never leave the server boundary
timer

External API Timeouts

All calls to external services (Google Safe Browsing, WHOIS, SSL checks) have hard timeouts of 7–10 seconds. External services are never trusted to respond in time — failures fall back gracefully rather than blocking.

Zero Trust Control: Never trust external systems to be available
cached

Cache TTL Enforcement

Scan results are cached for 24 hours maximum to prevent stale threat data from being served. A newly blacklisted site will be re-evaluated after the TTL expires — the cache is never trusted indefinitely.

Zero Trust Control: Treat cached data as potentially outdated
public

CORS Policy

Cross-Origin Resource Sharing is configured via FastAPI CORSMiddleware. In production, origins can be locked to the deployed domain only, preventing unauthorized third-party sites from calling the API.

Zero Trust Control: Explicitly allowlist permitted origins

history How User History is Protected

✓ No user identity stored. Scans are recorded with URL, score, and timestamp only. There is no user account, no login, and no way to attribute a scan to a person.
✓ No IP logging. The backend does not store the requesting IP address alongside scan records in the database.
✓ No session cookies. NebulaScan sets no tracking cookies. Results are passed between pages using sessionStorage, which is cleared when the browser tab closes.
✓ History is deletable. Scan records can be deleted individually or cleared entirely via the API — no permanent data lock-in.
✓ Local database only. The SQLite database (nebula.db) lives on the server only and is never exposed to the client.
